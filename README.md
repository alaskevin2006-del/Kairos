# Kairos 1.1

Windows 客户端与网页服务，共享总览、秘书、目标、回顾。用户决定安排，模型整理、维护自由 Markdown。品牌沿用用户提供的 assets/logo.png，打包钩子替换全部旧图标资源。

## 使用

网页 https://124.221.230.69/kairos/；管理员独立使用 /kairos/admin/，不访问个人空间。设置里保存自己的模型连接：名称、URL、模型、API Key 和高级 JSON 参数。当前支持 OpenAI 兼容 Chat Completions；秘书需要模型工具调用能力，不预设模型名称。

秘书接收任意安排、通知或进展，先查已有文档再更新或创建，显示实际改动及撤销入口。“保存原文”不调用模型、不自动转待办。日程详情可直接标记完成。日期过去不自动完成。

周日程区分课程、时间块、截止及仅有日期的活动。只有明确 DDL 缺少时刻才默认当天24:00。月历默认突出截止和重要事项，课程可切换，点击日期查看当天详情。目标直接阅读 Markdown；回顾显示日记和总结，区分生成日期、记录日期与更新时间。请秘书总结时先读取依据，每次独立保存。

## 文档、版本与同步

服务器各账号数据位于 DATA_DIR/spaces/<account-id>/，documents/ 是实际 Markdown。元数据、日程索引、历史和模型连接与原文分开保存。原账号 ID 为 owner。现有快照账号先导入原文，新普通账号直接从空白文档空间开始。

写入前比较文件内容哈希，批量提交前全部核对；保存修改前版本，中断时恢复未提交事务。撤销核对版本，不覆盖后续修改，新建文档的撤销也可恢复。秘书只有搜索、阅读、文档提交工具，无系统命令和跨账号访问。服务重启不重放未完成模型请求。

本地读取所选目录，兼容 _attention.md、Context 和课程 HTML；新文档按需放 tasks/、goals/、plans/。不要求统一模板。秘书维护派生日程索引，原文变化使旧索引失效；任务、计划中的复选框日期有保守兼容解析，复杂自然语言需模型整理。目标和日记正文直接刷新。

客户端运行期间约15秒按上次共同版本同步文件。并发修改和首次连接的不同内容保留冲突，设置中比较选择；删除不自动跨端传播，关闭客户端时不后台同步。服务器拒绝旧版客户端全量快照覆盖文档空间。

客户端设置可进入服务器空间，菜单可切回本地。两种空间分别保存模型连接，API Key 不随文档同步。同步令牌只允许同步和读取展示，不能调用秘书或管理模型。

## 构建

```powershell
npm install
npm run build
npm test
npm run desktop
npm run package
```

产物 release/Kairos-1.1.0-Windows.exe。同步密钥由 Electron 系统加密保存；模型密钥单独使用 AES-GCM 加密，接口只返回是否配置。

工具协议参考 [OpenAI 官方文档](https://developers.openai.com/api/docs/guides/function-calling)。测试使用隔离模拟模型和本地兼容 HTTP 服务，覆盖工具闭环、密钥、账号隔离、版本冲突、事务恢复及撤销；不代表已验证用户真实服务商的模型效果。

## 部署

Node.js22及以上，服务端只依赖内置模块。使用原有 HOST、PORT、DATA_DIR、KAIROS_PUBLIC_PATH、KAIROS_USER、KAIROS_SALT、KAIROS_PASSWORD_HASH、KAIROS_SYNC_TOKEN。可选 KAIROS_ADMIN_USER、KAIROS_ADMIN_SALT、KAIROS_ADMIN_HASH 仅初始化管理员，已有账号不被环境变量重置。

网页通过 HTTPS 代理访问，管理 API 校验角色，账号之间隔离。服务器模式的模型接口要求 HTTPS，拒绝内网、回环和保留地址，固定验证后的 DNS 地址，不跟随重定向。本地模式支持本地 HTTP 模型。高级参数不能覆盖秘书消息、工具、模型及流式协议字段。

独立目录和容器部署，更新前备份应用和数据，保留既有根站点。不要将 .private/ 中的凭据、部署工具或测试数据放入静态目录或安装包。
